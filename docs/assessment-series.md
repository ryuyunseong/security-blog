# 주통기 대상별 작성 순서와 목차

2026 KISA 가이드의 장 순서로 이어 쓴다. 한 대상의 모든 항목을 공개한 뒤 다음 대상의 첫 항목을 작성한다. 주통기 전체에서 하루 최대 한 편이며 대상이 바뀌는 날에도 두 편을 발행하지 않는다.

| 순서 | 대상 ID | 표시 이름 | 항목 | 편수 |
| --- | --- | --- | --- | --- |
| 1 | unix | Unix | U-01~U-67 | 67 |
| 2 | windows | Windows 서버 | W-01~W-64 | 64 |
| 3 | web-service | 웹 서비스 | WEB-01~WEB-26 | 26 |
| 4 | security-device | 보안 장비 | S-01~S-23 | 23 |
| 5 | network-device | 네트워크 장비 | N-01~N-38 | 38 |
| 6 | control-system | 제어시스템 | C-01~C-51 | 51 |
| 7 | pc | PC | PC-01~PC-18 | 18 |
| 8 | dbms | DBMS | D-01~D-26 | 26 |
| 9 | mobile | 이동통신 | M-01~M-04 | 4 |
| 10 | web-application | 웹 애플리케이션 | CI, SI 등 가이드 항목순 | 21 |
| 11 | virtualization | 가상화 장비 | HV-01~HV-25 | 25 |
| 12 | cloud | 클라우드 | CA-01~CA-19 | 19 |

전체 382항목의 코드·제목·중요도·본문 PDF 페이지 범위는 `src/data/assessment-catalog-2026.json`에 보관한다. 자료는 [KISA 공식 게시물](https://www.kisa.kr/2060204/form?postSeq=22&page=1)의 첨부 PDF이며, 해시 대조 후 목차 3~6쪽과 각 장의 항목표·본문을 조회했다. 원문 SHA-256은 `44fe393981b244147be6af7423d99dc15633c089fad0bcb296cbe2371dde812d`다. 원문의 C-39·HV-09 본문에는 중요도 오기가 있어 항목표 471·788쪽의 하·중을 사용하며 해당 항목의 `importanceNote`에 차이를 남긴다. 자동화 공격의 본문 777쪽은 쿠키 변조와 같은 CC로 표기되어 있어 항목표 678쪽의 AU를 사용하고 `pdfCode`·`codeNote`로 본문과의 차이를 보존한다.

## 다음 글 선택

1. 모든 대상의 공개 글을 시리즈별로 나눠 `seriesOrder`의 연속성·중복·범위를 대조한다. 앞선 대상의 공개 항목이 모두 있어야 다음 대상으로 넘어간다.
2. 아직 끝나지 않은 첫 대상에서 가장 이른 미완료 항목을 선택한다. 초안·미래 날짜 글은 완료에 포함하지 않는다. 해당 항목에 이미 초안이나 예약 글이 있으면 새로 생성하거나 다음 항목으로 건너뛰지 않고 이어서 검토한다.
3. 한국 날짜의 주통기 글 또는 초안이 대상 하나에라도 있으면 그날 새 주통기 글을 추가하지 않는다. 일반 Unix·코딩 테스트 글은 이 상한에 포함하지 않는다.
4. 선택한 항목의 원문 PDF를 다시 내려받아 해시·코드와 페이지 범위를 대조한다. 제목·중요도·적용 제품/버전·양호/취약 기준은 실제 원문으로 검토한다. 원문 변경이나 판단 기준의 불명확함은 해당 글을 보류할 이유이며 다른 대상이나 임의의 항목으로 대체하지 않는다. Qualys는 독립적으로 진행할 수 있다.
5. 모든 대상을 마치면 주통기 완료를 알리고 종료한다. Qualys와 허용된 추가 실습은 계속할 수 있다. 새 기준 연도를 자동으로 혼합하거나 2026 항목 범위 밖의 번호를 만들지 않는다.

## 대상별 목록과 목차

모든 주통기 글은 `category: critical-infrastructure`, `assessmentTarget: 대상 ID`, `series: 대상 ID-2026`, `seriesOrder: 1부터 시작하는 가이드 순서`를 지정한다. 일반 Unix 글에는 점검 대상을 쓰지 않는다. 대상·연도가 다르면 같은 순서 번호를 사용할 수 있으며 서로 다른 시리즈로 취급한다.

대상별 목록은 `/categories/critical-infrastructure/대상-ID/`, 해당 연도의 목차는 `/series/critical-infrastructure-대상-ID-2026/`이다. 공개 글이 있는 대상과 시리즈만 빌드하며 첫 글이 공개되면 목록·번호순 목차·대상 탐색·사이트맵에 자동 반영된다. 미래 대상의 빈 페이지나 링크를 미리 만들지 않는다. 기존 Unix 주소는 유지한다.

웹 서비스(`web-service`, WEB 코드)는 웹 애플리케이션(`web-application`, CI·SI 등)과 구분한다. 웹 애플리케이션의 `seriesOrder`는 가이드의 1~21 순서이며 제목·글 주소에는 실제 항목 코드를 사용한다. 첫 글은 `CI: 코드 인젝션 (Code Injection)`, 글 주소 접두사는 `ci-`다. 다른 대상도 원문 코드에 맞춰 `w-01-`, `hv-01-` 등을 사용한다.

## 실행과 발행 범위

`scripts/daily-publish.mjs`의 주통기 생성 작업은 `kind: assessment`를 쓴다. 계획 버전 2의 `assessment`, `next`, `assessmentTitle`, `progress`가 현재 대상·항목·완료 상태를 담는다. 모델 출력은 대상이나 시리즈를 지정하지 않으며 발행 코드가 고정된 계획에서 메타데이터를 채운다. 기존 버전의 생성 JSON을 새 계획에 재사용하지 않는다.

예제는 가상 파일·작은 데이터·루프백 등 승인된 격리 환경에서 실행한다. Windows·보안 장비·제어시스템·클라우드의 실제 계정이나 운영 설정 변경, 외부 스캔·API 호출을 수행하지 않는다. 운영 환경 없이 작성하는 항목은 설정 자료의 해석과 가상 예제의 범위를 분명히 구분하며 가짜 제품 화면·실행 결과를 만들지 않는다. 코드·도식·출력·문체·모바일 검증은 기존 작성 기준을 따른다.
