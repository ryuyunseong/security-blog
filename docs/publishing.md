# 매일 발행 운영

매일 한국 시간 오전 9시에 이 채팅의 예약 작업을 시작한다. 한 번의 실행에서 주통기 Unix 다음 항목 1편과 Qualys 글 1편을 작성·검증하고, 통과한 글만 main에 커밋·푸시해 Pages로 배포한다. 오전 9시는 작업 시작 시각이며 실제 공개는 검증이 끝난 뒤다.

## 주제 선택

- 주통기: 공개 글과 초안의 seriesOrder를 확인해 가장 이른 미완료 번호부터 진행한다. 현재 첫 후보는 U-11이다. 번호·제목·판단 기준은 2026 KISA 공식 가이드에서 다시 확인한다. 이미 발행한 번호를 재작성하거나 확인되지 않은 제목을 추측하지 않는다. Unix 항목을 모두 마치면 임의로 다른 분야를 시작하지 않고 완료를 보고한다.
- Qualys: 기존 글의 제목·내용과 대조해 중복되지 않는 실용 주제를 고른다. 후보는 자산 태그와 점검 범위, Asset Group과 Asset Tag, Search List, Option Profile, QID와 탐지 유형, 수집 시점과 상태 변화, 보고서 해석이다. 각 기능의 구독·앱·버전 조건을 공식 문서에서 확인한다.
- 날짜는 Asia/Seoul 기준으로 계산한다. 오늘 해당 종류의 글이 이미 준비되거나 발행됐으면 이어서 처리하고 중복 생성하지 않는다. 누락된 날짜를 채우려고 여러 날 분량을 한꺼번에 만들지 않는다.

## 작성과 검증

1. 저장소 상태와 원격 main을 확인한다. 다른 작업의 수정이 있으면 덮어쓰거나 자동 stash하지 않는다. 충돌을 해결할 근거가 없으면 발행을 멈추고 필요한 조치를 보고한다.
2. 공식 자료를 실제로 열어 번호·기능·판단 기준을 확인하고 출처 링크와 확인일을 적는다. 기준 가이드: https://www.krcert.or.kr/kr/bbs/view.do?bbsId=B0000127&menuNo=205021&nttId=71928 . Qualys 문서: https://docs.qualys.com/ . 구판을 혼용하지 않는다.
3. 한국어로 구체적인 상황에서 시작해 설정·명령·관찰·해석을 연결한다. 짧은 절과 상투적인 주의 문구를 반복하지 않는다. 실제 하지 않은 경험이나 고객 환경, 제품 운영을 꾸며 쓰지 않는다.
4. 실행 가능한 예제는 가상 파일·작은 데이터·루프백으로 실행한다. 운영 계정, 실제 인증·잠금, 원격 스캔, Qualys API·자격 증명은 사용하지 않는다. 제품 문서 해설에 제품 실행 결과를 만들지 않는다. 실행 불가한 코드는 이유를 적고 실제 출력과 예상 예시를 구분한다.
5. 설명 도식과 캡션·대체 텍스트를 추가한다. 사진·캡처는 내용 이해에 도움이 될 때만 사용하고 실제 제품 화면처럼 꾸미지 않는다. 코드 결과는 접근 가능한 텍스트로 제공한다.
6. 실행했다면 executions.json에 글별 recordedAt·environment·sourceCodeSha256·runs를 넣고 execution-context.json에 범위·해석을 적는다. 기존 글의 실행 날짜·환경은 바꾸지 않는다. 17편 재현 스크립트는 추가 결과를 보존한다. 본문 기준 정보나 테스트를 통과시키기 위해 검사를 느슨하게 하지 않는다.
7. 주통기와 Qualys는 각각 검증 가능한 작업 단위로 작성·검토한다. 하나가 근거 부족으로 보류되면 다른 하나는 독립적으로 진행할 수 있다. 기준을 충족하지 못한 글을 분량 때문에 발행하지 않는다.

## 발행

`node scripts/build-article-diagrams.mjs`, `npm run check`, `npm test`, `npm run build`, `npm run verify`를 실행한다. 별도 린터는 없다. 그림·표·코드·목차·실행 출력을 데스크톱과 모바일에서 확인하고 민감정보·과장·출처 불일치를 검토한다. 주통기 목차와 검색·RSS는 콘텐츠에서 자동 갱신된다.

사용자는 이 예약 작업의 검증된 글에 대해 커밋·푸시·Pages 배포를 승인했다. 작성한 글과 필요한 그림·기록만 명시적으로 스테이징하고 일반 커밋·푸시를 사용한다. 이력 재작성, 강제 푸시, 인증/배포 권한 변경은 일일 작업에 포함하지 않는다. Actions 성공과 공개 글·이미지·목차·RSS를 확인한 뒤 발행 링크·커밋·검증·남은 한계를 보고한다.

실패하면 허위 성공으로 기록하지 않는다. 작성 파일을 보존하고 같은 주제를 재시도하되 이미 올라간 글은 다시 만들지 않는다. 사용자에게 메시지나 이메일을 별도로 보내지 않는다.

## 실행 조건

로컬 예약 작업은 컴퓨터가 켜져 있고 Codex 앱과 프로젝트를 사용할 수 있어야 한다. GitHub 인증과 네트워크·파일 권한도 필요하다. PC가 꺼져 있어도 실행되는 GitHub Actions의 콘텐츠 생성 작업을 구성한 것은 아니다. 권한이나 공식 근거가 부족하면 그 글의 발행을 보류한다.
