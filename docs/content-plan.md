# 콘텐츠와 작성 기준

보안 설정을 읽고, 작은 실습으로 확인하고, 판단의 근거를 남긴다. 한국어를 중심으로 쓰되 명령·필드·제품 이름은 정확하게 유지한다.

현재 주통기 Unix U-01~U-10, 파일·웹·TLS·압축 실습 5편, 알고리즘 2편, Qualys 문서 해설 4편을 제공한다. 공개 글은 src/content/posts/에서 관리한다. 시리즈 범위와 글 수는 실제 콘텐츠에서 계산한다.

## 글의 구성

구체적인 상황이나 궁금증으로 시작한다. 설정값·확인 명령·관찰한 결과·해석을 연결하고, 독자가 다음에 확인할 지점을 남긴다. 목차를 채우기 위한 짧은 절이나 같은 주의 문구의 반복은 줄인다.

실행 가능한 코드는 격리된 환경에서 확인하고 출력과 종료 코드를 기록한다. 실행하지 못하면 이유와 범위를 적으며 예상 출력을 실제 결과처럼 표시하지 않는다. 기존 코드의 기준 정보는 content-baseline.json에 보관한다. 코드를 의도적으로 바꿀 때는 재검증 후 기준 정보도 함께 검토한다.

각 글에 설명 도식을 제공하고 필요한 곳에 사진·캡처를 추가한다. 사진 형태의 생성 이미지는 캡션에 생성 사실을 표시하며 제품 실행이나 개인 경험의 증거로 사용하지 않는다.

## 근거와 공개 범위

주통기는 해당 연도의 KISA 공식 가이드에서 번호·제목·양호/취약 기준·운영체제 범위를 확인한다. 제품 기능은 Qualys 공식 문서를 기준으로 버전·구독·권한 조건을 확인한다. 가이드 문구를 길게 복제하지 않고 직접 정리하며 출처와 확인일을 남긴다.

실제 운영 계정, 비밀번호·키·쿠키, 내부 환경과 원본 로그는 수집하거나 게시하지 않는다. 실습은 가상 파일과 루프백을 우선한다. 문서 해설과 직접 실행한 관찰을 구분하고, 제품 운영 경험이나 개인 역할을 꾸며 쓰지 않는다.

## 매일 발행

주통기 다음 항목 1편과 기존 글과 겹치지 않는 Qualys 주제 1편을 작성한다. 공식 근거와 검증이 충분한 글만 발행한다. 중복 실행·실패 재시도는 같은 글을 또 만들지 않도록 처리한다. 상세 절차는 [발행 운영](publishing.md)을 따른다.
