# 검증 및 인수인계

## 1. 변경 사항

- README와 작성·화면 문서를 현재 블로그의 기능과 운영 기준으로 정리했다. 사용하지 않는 외부 블로그 목록·출처 URL 자료를 제거했다.
- content-baseline.json에는 기존 21편의 발행일·시리즈 순서·코드 개수와 해시만 남겼다. 기존 코드 95개는 보존하며 새 글 추가를 허용한다.
- 주통기 목차의 마지막 번호와 글 수를 콘텐츠에서 계산한다. 일일 발행에서 다음 항목이 추가돼도 고정 문구를 고칠 필요가 없다.
- 실행 기록은 글마다 날짜·환경을 보관한다. 17편 재현기는 이후 글의 개별 기록을 보존한다. 기존 출력 자체는 변경하지 않았다.
- 보안 노트 매일 발행 예약을 활성화했다. 한국 시간 매일 오전 9시에 주통기 다음 항목과 Qualys 주제를 각각 최대 1편 작성·검증해 일반 커밋·푸시로 발행한다. 절차와 보류 조건은 publishing.md에 정리했다.
- 사용자 승인에 따라 기존 4개 커밋 제목을 블로그 구축·검증·개선 중심으로 정리했다. 복구용 로컬 참조를 보관하고, 각 커밋의 파일 트리·작성자·시각을 보존했다. 원격 반영에는 확인한 SHA를 명시한 force-with-lease를 사용했다. 예약 작업에는 이력 수정 권한을 부여하지 않았다.

## 3. 보안/품질 검토

- 인증/권한 영향: 사이트 인증·상태 변경 API와 운영 설정 변경 없음. 일일 글의 일반 커밋·푸시·기존 Pages 배포만 허용한다.
- 민감정보 영향: 이전 출처 URL 자료 제거. 실행 결과는 기존 가상 자료이며 실제 자격 증명·운영 로그는 사용하지 않는다.
- 입력 검증 영향: 기존 콘텐츠 스키마와 코드 해시 대조 유지. 새 글 수를 고정하지 않고 글·그림·실행 기록의 실제 일치를 검사한다.
- 로그 노출 가능성: 실습 출력만 게시. 예약은 발행 완료·실패·사용자 조치가 필요한 경우 결과를 보고한다. 호스팅 자체 로그 정책은 미확인.
- 기존 기능 회귀 가능성: 목차·실행 환경 표시 변경과 기존 콘텐츠 보존을 검증한다. 일일 발행 전체의 첫 무인 실행은 아직 미검증이다.
- 유지보수 리스크: PC·Codex 앱·프로젝트·GitHub 인증·네트워크 권한이 필요하다. 공식 근거·실행·검증이 부족하면 해당 글은 보류한다. 이력 변경 전 커밋 ID를 쓰던 외부 링크는 옛 기록을 가리킬 수 있고 외부 캐시 삭제는 보장하지 않는다.
