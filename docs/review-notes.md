# 검증 및 인수인계

검토일: 2026-10-16. 빈 폴더에서 Astro 블로그를 구현한 뒤, 사용자 승인으로 티스토리 글을 이전하고 공개 저장소를 생성했다.

## 변경 사항

- Astro 설정·공통 레이아웃·컴포넌트·스타일: 한국어 정적 블로그, 테마, 모바일, SEO, RSS
- src/content/posts: 티스토리 21편 이전, 최초 예제 5편은 초안 보관
- src/data/migration.json: 공개 원문 24편의 이전 여부와 코드 해시
- 글 스키마·상세·시리즈 페이지: 원문·발행일·이전일 표시, U-01~U-10 번호순 목차 및 이전·다음 탐색
- tests/migration.test.mjs: 이전 누락과 원문 코드 95개 보존 검사
- .github/workflows/deploy.yml: main 검증·자동 Pages 배포, PR 검증
- README와 docs: 공개 범위, 글별 이전 결정, 운영·검증 기록

## 검증 결과

Node.js 24.15.0, npm 11.12.1, Windows에서 확인했다.

- npm run check: 오류 0·경고 0·힌트 0을 최종 빌드 전 확인
- npm test: 기존 검사 5개와 이전 검사 4개, 총 9개 통과
- npm run build: 공개 글 21편과 전체 HTML 74개 생성
- npm run verify: Pages 하위 경로에서 내부 링크·앵커·SEO·RSS·검색·사이트맵 7,336개 검사 통과
- 코드 보존: 원문 코드 블록 95개를 개수·순서·본문 SHA-256으로 대조
- Python 문법: 표시된 Python 코드 13개 검사 통과
- 로그인 집계: 경계·동시각·중복 알림, 무작위 2,000건 비교와 입출력 확인 통과
- CIDR: 경계·잘못된 입력·입출력·병합·무작위 비교 5개 테스트 통과
- 브라우저: 전체 21편의 본문·원문 링크·코드 95개 렌더링과 복구한 표 제목 확인
- 탐색: 주통기 10편 순서, 원문·날짜, 목차, 코드 복사, 하위 경로 검색, 테마 저장 확인
- 모바일: 320px 시리즈 제목 넘침을 발견해 긴 단어의 줄 바꿈을 허용하고 재검증
- 정상 사용자 흐름의 콘솔 오류와 외부 자동 요청 0건을 최종 QA에서 확인

초기 앱 내 브라우저의 뷰포트·캡처 불안정 때문에 번들 Playwright와 기존 Edge로 검증했다. 캡처·원문 HTML·임시 스크립트는 저장소 밖에 보관한다. 별도 린터는 설정하지 않았다.

초기 검증의 환경 문제는 숨기지 않고 구분했다. 샌드박스 DNS·Astro 설정 폴더·자식 프로세스 접근 제한은 허용된 실행 경로와 텔레메트리 비활성 변수로 해결했다. Windows 개행 차이로 코드 대조 테스트가 실패해 비교에서 CRLF를 정규화했고, 번들 Python의 모듈 경로·기본 인코딩을 지정해 원문 테스트를 실행했다. 실패한 검사를 비활성화하지 않았다.

Linux 설정 수집기·PAM 인증·TLS/ACL 실습과 실제 Qualys 기능은 이번 이전에서 실행하지 않았다. 해당 관찰은 원문 작성 시점의 기록이며 새 환경에서의 재현을 보장하지 않는다. KISA 공개 출처와 일부 제품 공식 문서를 확인했으나 모든 참고 링크·가이드 세부 기준의 전수 감사는 수행하지 않았다.

## 보안·품질 검토

- 인증/권한 영향: 방문자 인증·상태 변경 API 없음. GitHub 배포 권한은 deploy job에만 부여.
- 민감정보 영향: 공개 원문의 본문만 이전. Tistory 스크립트·페이지 토큰·쿠키·로컬 자료는 제외. 고정 실습 문자열은 원문에서 실제 자격 증명이 아님을 표시.
- 입력 검증 영향: 글 스키마의 카테고리·태그·날짜·출처·시리즈 순서 검증. 검색은 textContent로 렌더링.
- 로그 노출 가능성: 방문자 검색 로그 수집과 분석 도구 없음. 호스팅 서비스 자체의 로그 정책은 미확인.
- 회귀 가능성: 이전 완전성과 코드 보존·주요 탐색을 검사. 실제 운영 환경에서 예제 코드를 실행한 검증은 아님.
- 유지보수 리스크: 글 갱신과 예약 날짜 공개에 재빌드 필요. 파일명 변경은 주소에 영향. 제품 문서와 점검 가이드 변경 시 내용 재검토 필요.

## 현재 배포 상태

사용자 승인 완료. 공개 저장소 ryuyunseong/security-blog 생성과 PAGES_DEPLOY_ENABLED=true 설정 완료. 최종 소스 검토·커밋·푸시·원격 Actions 및 공개 URL 검증을 이어 진행한다.
